# Notes

## Learner

- Working programmer, mainly frontend, some backend and API experience. Comfortable with HTTP as a client-side concept; building out systems, ops and security.
- Has been leaning on AI for coding; wants to keep hand-coding skills sharp (`../practice/` is AI-free).

## Preferences

- Short lessons; uneven weekly energy. A lesson should be doable in a sitting.
- Wants durable, referable notes that others can read too (repo is public). Keep personal details out of committed files.
- Security is the thread through every topic: ask "how does this get attacked, and how is it mitigated?"
- Hands-on practice welcome: can use local machine, containers, AWS.

## Working agreements

- Workspace is `teach/`. Session log lives in `../log/`. Commit as the user (repo git config), push to a branch, merge via PR.

## Session routine

- Warm-up before any new lesson: 3 or 4 questions from memory, from records whose re-test is due. Typed answers in my own words, not multiple choice. Give feedback right away: what was right, what was missing, the correct answer in a sentence or two.
- After a gap of more than a week, make the warm-up a gentle recap and keep the lesson short.
- End of lesson: ask me to explain the idea back in my own words, correct the gaps, and put the corrected version in the learning record.
- Every learning record ends with "Re-test: on or after <date>" (1 day, then 3, 7, 14; up when I get it right, back when I don't).
- Wrap-up: add one line to ../log/YYYY-MM.md, commit to a branch, open the PR, and tell me in one line what to do next time.
