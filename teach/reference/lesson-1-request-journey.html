The request journey

Quick-reference notes from networking lesson 1. Every claim comes from MDN or HPBN (linked at the bottom).

The four steps

  1. Address lookup. The browser asks DNS for the IP address of the server the site lives on. It needs this before it can retrieve the site.
  2. Request. The browser sends an HTTP request asking for a copy of the site. All data between client and server travels over TCP/IP.
  3. Response. If the server approves, it replies 200 OK and sends the site's files as small chunks called packets.
  4. Assembly. The browser puts the chunks together into the page.

Where each step fails

SymptomStep
Can't find the site at all1. Address lookup (DNS)
Data lost or corrupted on the way2-3. TCP/IP transport (client re-requests the missing packets)
Error code (403, 404, 503...)3. Response (server answered, not with the page)

Status codes

CodeMeans
200Success
301Permanently moved; the new location is in the response
400Server can't process the request (malformed or has errors)
403Server won't give access: it knows who you are, but you lack permission
404Can't find the resource (wrong URL, or deleted without a redirect)
503Server can't handle the request right now, usually temporary (e.g. maintenance)

Mix-ups to watch: 301 is not "unauthorized" and 503 is not "internal server error". Those are different codes (401 and 500), which the MDN page names but doesn't define; look them up in MDN's HTTP status reference.

Packets

Data is sent in small chunks. Each packet has a header (client and server IP addresses, packet number, total packets, protocol details) and a payload (the actual data).

Why chunks: (1) dropped or corrupted packets can be re-requested on their own instead of the whole file; (2) packets can take different routes and arrive out of order, and the header numbers let the client reassemble them.

TCP/IP vs HTTP

TCP/IP defines how data travels across the internet (the road and the vehicle). HTTP is the application protocol: the language client and server use to talk (the order you place at the shop). DNS is the address book that turns a domain name into an IP address.

TLS: three services, three attacks

ServiceWhat it doesAttack it answers
EncryptionObfuscates what is sent between hostsReading the traffic
AuthenticationLets the browser verify the server is who it claims to beImpersonating a site (spoofing its name or IP address)
IntegrityDetects tampering and forgery, using a message authentication code on each messageChanging the traffic

MDN: HTTPS is a secure version of HTTP that stops bad people from reading your data while it is being transported.

Try it

curl -sI https://developer.mozilla.org/en-US/
curl -sI https://developer.mozilla.org/en-US/no-such-page-xyz

-I asks for headers only. Expect HTTP/2 200 for the first and 404 for the second.
