# How to learn

Notes on learning better in general, and how I apply each idea in this repo. It's a notebook with its own small review queue, not a study workspace.

## Mastery learning, in my words

My first explanation of it, written from memory after reading part of an article:

> Mastery learning is when you focus on nailing a concept before moving on. You should get around 90% before moving on. This will help prevent holes or gaps in knowledge so it lowers the chance you have to go back and fill those in. You focus on depth instead of time line. I want to apply to my own studying: reduce knowledge gaps before moving on because you need a solid foundation to build on.

What I missed in that summary is listed in `gaps.md`, so I can fix it from memory.

## What changed in my rules because of it

1. **A different explanation, not a repeat.** When a miss repeats, change the representation instead of re-explaining the same way (in each workspace's `NOTES.md`).
2. **A threshold.** About 85 percent on a topic or block review quiz, within the usual 80 to 90 percent (each `PLAN.md` and `NOTES.md`).
3. **A decision after each topic check:** move on, correct, or enrich, noted in the learning record (each `NOTES.md`).
4. **A transfer test.** Each block ends with something unfamiliar, not only recall questions (each `PLAN.md`).
5. **The time tradeoff.** With a fixed end date, a block that needs longer means later blocks shrink (each `PLAN.md`).

## Limits to keep in mind

From the article's own critiques; I haven't checked the originals.

- Tests that closely match what was taught can overstate gains (Slavin, 1987).
- If the standard is fixed, time must vary, and real schedules are fixed (Arlin, 1984).
- Mastery learning bundles several ingredients: formative checks, feedback, corrective teaching and extra time.
- It was written about school classes, so using it for self-study is by analogy.
